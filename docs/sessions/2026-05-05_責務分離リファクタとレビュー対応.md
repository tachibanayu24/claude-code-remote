## 1. 完了通知の高機能化

通知 body に「経過時間 + 直近の assistant text の preview」を出し、タップで Compose の `CompletionDialog` に全文をスクロール表示。背景タップで閉じれる。

主な追加:
- `backend/src/format.ts` — `formatElapsed`, `previewLine`
- `android/.../notification/CompletionPayload.kt` — bundle 詰め替え
- `android/.../ui/CompletionDialog.kt` — `verticalScroll` + `SelectionContainer`
- `MainActivity` で `ACTION_VIEW_COMPLETION` を捌く

加えて Stop hook の閾値判定（デフォルト 3 分）を導入し、短いターンでは push を飛ばさないように。

## 2. 責務分離リファクタ

ユーザーから「mjs はもっと薄くしていいんじゃない」と指摘。元々の mjs は formatElapsed や title 構築まで持っていた。

整理後:
- **mjs (PC)** — `~/.claude/projects/.../<sid>.jsonl` の読み取り（PC でしかできない）と raw データ抽出のみ。243 → 203 行
- **backend (Workers)** — title/body 整形、threshold 判定、FCM 送信
- **channel.mjs** — Channels permission relay、touch せず

mjs の `formatElapsed` `previewLine` `shouldNotifyStop` `makeClient` `notifyStop` `dismissPending` ラッパーや `kind` 文字列リテラル / `project_name` 導出を削除し、jsonl パーサだけ残置。

「もっと究極まで薄く」案 (jsonl の tail を丸ごと backend に送って backend でパース) も検討したが、巨大な単一行 entry で末尾切断耐性が要るなど tricky なのでパーサは PC に残す決定。

## 3. 新エンドポイント

| 旧 | 新 |
|---|---|
| `POST /v1/notifications` | `POST /v1/hook/stop`（dismiss + threshold + 完了通知を 1 リクエストに集約）|
| `POST /v1/approvals/dismiss_pending` | `POST /v1/hook/posttool`（cwd 必須） |

旧 endpoint は完全削除。Android の test notification 経路も `/v1/hook/stop` で `elapsed_ms` を threshold 超で送る形に追従。

## 4. dry_run フラグ

検証時に curl で本番 backend を叩くと登録デバイスに実通知が飛んで二重通知になる事故を踏まえ、`dry_run: true` を追加。FCM 送信と D1 insert をスキップして `would: { title, body }` を返す。

## 5. 全層コードレビュー

3 並列 agent で backend / mjs / Android をレビュー。重要度順に修正。

### Critical / High（修正済み）

| # | 何 | どう |
|---|---|---|
| 1 | `/v1/hook/posttool` 空 cwd で全 session 一括 dismiss | `cwd` 必須化、空なら 400 |
| 2 | Edit/Write allowlist パターンが literal path で機能しない | `deriveAllowPattern` から Edit/Write/MultiEdit を除外 |
| 3 | `settings.local.json` 書き込みが非アトミック | tmp + rename |
| 4 | `allowBackup="true"` で SHARED_SECRET が adb backup で抜ける | `false` に |
| 5 | Bearer 比較が timing-unsafe | SHA-256 ハッシュ後 byte XOR で constant-time |
| 6 | FCM 失敗時に stale token が残り続け、`notified` が attempted 数 | `FcmInvalidTokenError` 新設、404/INVALID_ARGUMENT で `devices` から削除、成功数を返す |
| 7 | ApprovalDialog が背景タップ/戻るで閉じて respond されない | `dismissOnBackPress=false` `dismissOnClickOutside=false` |
| 8 | `onNewIntent` で `setIntent` していない | 追加 |

### 意図的に skip
- FCM data payload に shell command 全文が乗る件 → `request_id` だけ送って Android で fetch に変えるのは大改造、個人用途で許容。`docs/handover.md` §12 に記載。
- channel polling の backoff、`getSessionLabel` の ppid 依存、`dismissPendingApprovals` の TOCTOU → 1 ユーザー scale で実害なし

### 誤指摘
- Compose 二重 VM 警告（`viewModel()` と `ViewModelProvider(this)` は同一 store に解決される）

## 6. 学び・残課題

- 自分で curl smoke test 打って実機に通知が飛ぶ「セルフ通知 spam」現象を経験。`dry_run` の存在意義は実体験から。
- レビュー agent の指摘は鋭いが鵜呑みは危険（Compose の件、`dismiss before threshold` の意図解釈ミスなど）。一次資料として自分で再確認することが必須。
- handover.md は「最初の設計案」が時間とともに陳腐化する典型例だった。実装が進んだら一度全文書き直すリズムを確立したい。
