# 2026-05-05: Channels permission relay へ方針転換

## TL;DR

PreToolUse hook ベースの自前実装を捨て、**Claude Code Channels の permission relay** (research preview) を採用する設計に切り替えた。理由は、CLI native dialog と phone push を **完全並走** させ、**先着優先で他方を自動キャンセル** するという要件が hook では絶対に作れないため。Channels protocol は CC 内部でこれを公式実装している。

## 経緯

### 当初実装の問題

- `PreToolUse` hook を `Bash|Edit|Write|MultiEdit|mcp__.*` に張り、全 tool を backend にルートしていた
- 実は `PreToolUse` は **permission チェック前** に発火するため、auto-allow されるはずの tool でも毎回 phone 通知が飛ぶ
- 結果: `ls` 一発でも通知が来る、ユーザの作業が止まる
- さらに、自前で `/dev/tty` を読む TUI を hook 内に書いて CLI 操作と phone を race させていたが、これは CC native UI と並走しない（hook 実行中は native dialog が出ない）

### 妥協案 (PermissionRequest hook + ntfy 系) の検討

`yuuichieguchi/claude-remote-approver` の方式を参考にした:
- `PermissionRequest` hook (auto-allow では発火しない hook) + ntfy
- Phone 応答が無ければ 120s 後に `ask` を返して native dialog にフォールバック

**致命的な欠点**: 120s 待たないと native dialog が出ない。PC で集中作業中は耐え難い UX。
ユーザ判定: 「妥協は致命的、やらないほうがマシ」。却下。

### Remote Control の検討

公式 Remote Control (Claude mobile app) は claude.ai/code の interface を使う。`v2.1.110+` で mobile push notifications あり。
**欠点**: mobile app から「allow ボタン」で permission を返す UI が無い。メッセージ送信ベース。permission 専用ではない。要件不満足。

### Channels permission relay (採用)

Claude Code v2.1.81+ で導入された公式機能 (research preview):
- カスタム MCP server が `claude/channel` + `claude/channel/permission` capability を declare
- CC が `notifications/claude/channel/permission_request` を server に送る
- Server が `notifications/claude/channel/permission` で verdict を返す
- **Native CLI dialog は開きっぱなし**、phone への relay と並走
- **First-come-first-served は CC 内部で実装済み**、自前 race 不要

要件全部満たす唯一の手段。

## 新アーキテクチャ

```
Claude Code (PC)
  ├── Native permission dialog (CLI で操作可)
  └── MCP channel server (channel/channel.mjs, Node stdio subprocess)
        │
        ├─ permission_request (request_id, tool_name, description, input_preview)
        ├─→ HTTP POST → Workers backend /v1/approvals
        │       └─→ FCM push → Android (Allow/Deny ボタン)
        │
        ├─ 1秒間隔で /v1/approvals/:id を poll
        │
        └─ verdict 取得 → notifications/claude/channel/permission emit
              └─ CC が dialog を close、tool 実行 (or block)
```

PC で答えた場合: native dialog が即時 close、CC が channel server に「もう pending じゃない」を伝える形で他方が drop される (CC 仕様)。

Phone で答えた場合: backend が `approval_resolved` FCM dismiss を全デバイスに送って通知をキャンセル。CC は channel server からの verdict で dialog を close。

- `channel/package.json` — `@modelcontextprotocol/sdk`, `zod`

### 修正

- backend の `summarize()` ヘルパー

## 起動コマンド

```bash
claude --dangerously-load-development-channels server:cc-remote
```

`--dangerously-load-development-channels` は research preview 期間中の必須フラグ (Anthropic 公式 marketplace に登録されるまで)。

### `--dangerously-load-development-channels` のリスク

このフラグは Anthropic がキュレーションする channel allowlist を **bypass** する。具体的には:

1. **CC は通常、channel として登録できる MCP server を Anthropic 承認済みに限定している**
   - Telegram, Discord, iMessage, fakechat の 4 つだけが research preview の allowlist 入り
   - これは channel が `claude/channel/permission` capability を declare すれば **CC のすべての permission prompt を傍受できる** ためのセキュリティ境界
2. **このフラグで bypass すると、任意の MCP server が channel として動ける**
   - 起動時に per-entry の確認ダイアログは出るが、一度 yes すると以後そのまま
   - 悪意ある MCP server が同フラグで読み込まれた場合、permission_request を傍受して `behavior: 'allow'` を勝手に emit できる (= ユーザに見えないところで全 tool 許可)
   - 複数 channel 登録時は **先着 verdict が勝つ** ため、悪意 channel が一番速く allow を返せば、ユーザの phone 操作は無効化される
3. **本プロジェクト固有のリスク** は低い (channel server は自作・auditable、shared secret は `~/.claude/hooks/.env` に chmod 600 で保管):
   - secret 漏洩 → attacker が backend に approval を POST できる (が CC 起動側に届かない、phone 通知が増える程度)
   - secret 漏洩 + 既存 request_id 推測 → 本来 phone 経由で答えるべきリクエストを attacker が `respond` で勝手に解決できる。ID は backend UUID なので推測困難
4. **第三者 MCP server を一緒に同フラグで読み込むのは絶対に避ける**
   - 他 plugin を development flag で混ぜない、or `claude/channel/permission` capability を declare してない channel に限る

将来公式 marketplace に登録できれば `--channels plugin:cc-remote@<marketplace>` が使え、 security review 済みになる。

## 制約・前提

- Claude Code v2.1.81+ 必須 (現在 v2.1.126 なので OK)
- claude.ai login 必須 (Console / API key 不可)
- Pro/Max ユーザ
- Bun は不要 (公式 docs で Node OK と明記、@modelcontextprotocol/sdk は Node で動く)

## 議論メモ

- Channels が公式 marketplace に登録されたら `--channels plugin:cc-remote@<marketplace>` で起動できる。security review を経る必要がある。当面は development flag で運用。
- `device_id` 重複問題（DataStore リセットで新 UUID が振られて積み重なる）は backend 側で `fcm_token` 重複行を DELETE する形で根本対応済み。
- Stop / Notification (idle_prompt) hook は permission relay と独立に動く。処理完了通知 / 入力待ち通知用。
