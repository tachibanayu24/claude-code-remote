# 2026-05-05 全層リファクタ

Phase 3 完了後、全層 (Android UI/Core, channel/hooks, backend, migration) を Sonnet サブエージェントでレビューし、その結果を統合して大規模 cleanup を実施。

## 経緯

ユーザーから「コードがぐちゃぐちゃ。リファクタ・潜在バグ撤廃・UX/UI 改善を全面的にやってほしい」と依頼。`/effort max` で 4 並列の Sonnet サブエージェントを backend / channel+hooks / Android core / Android UI に投げ、優先度付きで findings を回収。Phase A (security/correctness) → Phase B (refactoring) → Phase C (UX) → Phase D (migration/build/deploy) の順に実装。

## 主な変更

### Backend (Hono + D1)

- **route 分割**: `index.ts` 480 行を `routes/{devices,approvals,sessions,hooks,prompts}.ts` に。auth は `auth.ts`、共通 db helper / cleanup を `db.ts` に
- **race condition 解消**: `dismissPendingApprovals` を `UPDATE ... RETURNING id` に切り替え、SELECT → UPDATE の TOCTOU を排除。同 cwd への並走 Stop hook で FCM 二重発火していた箇所を修正
- **GET の副作用排除**: cleanup-on-read を `c.executionCtx.waitUntil(...)` に。レスポンス送信後にバックグラウンドで実行されるので HTTP セマンティクス的に GET が READ-ONLY を保つ
- **D1 batch**: `/v1/sessions` で sessions + pending を、`/v1/sessions/:cwd/turns` で turns + pending + queued を batch 化
- **type 整合性**: `add_to_allowlist` を `Number(...) === 1` で正規化、`/v1/prompts/:id/delivered` の "already delivered" を 409 に
- **FCM**: token cache に single-flight、INVALID_REGISTRATION/UNREGISTERED を JSON ベースで判定、token prune を `IN (?, ?, ...)` の bulk DELETE に
- **migrations**: 0007 `approvals.reason` (dead) drop / 0008 `idx_turns_ended` / 0009 `idx_approvals_cwd_status`

### Channel + Hooks (Node.js)

- **8 関数の重複解消**: `channel.mjs` と `hooks/cc-remote-hook.mjs` で完全に重複していた jsonl パーサ群 (`SYNTHETIC_USER_WRAPPERS`, `isSyntheticUserEntry`, `userEntryText`, `lastUserPromptFromJsonl`, `hasEndTurnAfter`, `assistantTextsAfterFromJsonl`, `aiTitleFromJsonl`, `loadEnv`, `encodeCwd`) を `hooks/lib/{jsonl,env,cwd}.mjs` に集約
- **transcript_path 利用**: 新しい Claude Code hooks の stdin payload に `transcript_path` が来るので、これを直接 `readFileSync` する fast path を追加。fallback の `readdirSync` 全プロジェクトディレクトリ走査が不要になる
- **AbortSignal**: channel.mjs `pollAndEmit` の `apiGet` に `AbortSignal.timeout(POLL_INTERVAL_MS - 100)` を渡し、ハングした 1 リクエストが次以降の poll をブロックしないように
- **silent failure 解消**: hook の `post()` が HTTP error をログに残す、config 欠損時の `process.exit(1)` を log → `exit(0)` に変更 (CC が失敗扱いしないように)

### Android (Kotlin + Compose)

#### Lifecycle / Concurrency

- **`BackendClientHolder`**: process-wide singleton で OkHttp connection pool を共有。call ごとに `BackendClient(config)` を new + close していた箇所を全廃
- **`MainViewModel`**: MutableStateFlow 9 本を `data class UiState` 1 本に集約、`init { }` 2 つを 1 つに統合し bootstrap → config 同期 → FCM 登録 → home poll の順序を明示
- **`MainActivity`**: `by viewModels()` で VM 二重生成を解消、`Screen` sealed class でナビ管理 (`Home / Detail(cwd) / Settings`)
- **`CoroutineScope` 修正**: `CcRemoteMessagingService` は `SupervisorJob` を持ちフィールドに保持・`onDestroy` で cancel、`ApprovalActionReceiver` は `goAsync()` 内で SupervisorJob 付き scope を毎回作る
- **`ConfigStore.flow`**: `IOException` を catch → `emptyPreferences()` で degrade

#### UI / UX

- **HomeScreen**: `PullToRefreshBox` (M3 1.3+)、`derivedStateOf { sessions.partition(...) }`、状態 dot の凡例 row、`SessionRow` に `role = Button` + 日本語 `contentDescription`
- **SessionDetailScreen**: `last_heartbeat` を `produceState` で 1s ごとに評価し input bar の enabled をリアルタイム反映、コマンド/ターンを `SelectionContainer` でコピー可能に、in-flight bubble の dot を `infiniteRepeatable` で pulse、Approval ボタン3種に `LocalHapticFeedback`
- **ChatMarkdown**: `LinkAnnotation.Url` (Compose 1.7+) でリンク tap 可能に
- **SetupScreen**: URL/secret に inline validation (URL prefix チェック、secret 16 文字以上)、`isError` + `supportingText`
- **SettingsScreen**: 表示中のみ `FLAG_SECURE` を立て、screenshot/recent-task に secret が漏れない
- **ClawdLogo**: `mutableStateOf<Job?>` をやめ、recomposition を伴わない `JobHolder` に。`onClickLabel` で a11y 補強
- **Theme**: `outlineVariant` を明示

#### Security / Build

- **DataStore backup 除外**: `data_extraction_rules.xml` / `backup_rules.xml` の `domain="sharedpref"` (DataStore に効かない) を `domain="file" path="datastore/cc_remote_config.preferences_pb"` に修正。`allowBackup=false` も維持
- **R8 minify**: `release` を `isMinifyEnabled = true` + `isShrinkResources = true`、`proguard-rules.pro` に kotlinx.serialization / Ktor / Firebase / Compose の `-keep` ルール
- **Manifest**: `tools:targetApi="34"` → `35`、`InvalidFragmentVersionForActivityResult` lint を disable (ComponentActivity ベースで Fragment 不要)

### 共通

- 既存の Approval command 抽出ロジック (`SessionDetailScreen.approvalCommand` と `ApprovalPayload.detail` で重複) を `data/ApprovalCommandFormatter` に集約
- `NotificationFactory.showInfo` の通知 ID を `System.currentTimeMillis().hashCode()` から `AtomicInteger` に (同一ミリ秒衝突を排除)
- CATEGORY を `REMINDER` から `EVENT` に (Material guideline 準拠)

## 残課題 / 次の打ち手

- backend のテスト皆無 (timing-safe bearer / format helper / fcm error parsing は単体テストの費用対効果が高い)
- Android のテスト皆無 (`BackendClient` モック、`ApprovalCommandFormatter` の extractKey edge case)
- channel.mjs の `appendAllowPattern` の read-modify-write race (CC 自身がほぼ同時に書いた場合の衝突)。flock 不可、ループリトライ + mtime チェックで検出は可能
- 巨大 jsonl (>100MB) で channel heartbeat の `readFileSync` がメモリ膨張する。tail-only パーサに切り替えると改善
- Compose BOM / Firebase BOM / coreKtx の version up は CI に dependencyUpdates を仕込んでから
