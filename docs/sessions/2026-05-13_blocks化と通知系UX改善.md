# 2026-05-13 blocks 化 / 通知系 UX 改善 / セルフレビュー

運用 1 週間で見えてきた phone 側 UX の不満を順に潰した。中心は (1) FCM 通知の到達性、(2) チャット表示順序、(3) 操作の整合性、(4) tool_use 表示の情報密度。終盤で AskUserQuestion relay の事前調査と設計だけ済ませて保留。

## 経緯

phone から「アプリ開くまで通知が来ない」「メッセージとコード差分の順序が CLI と違う」「Always がないツールで Always 押すと握りつぶされる」「Bash のハイライト変」「TaskCreate の中身が見えない」と立て続けに指摘が来たので、それぞれ最小修正で潰した。AskUserQuestion 対応は Phase 1 (notify-only) / Phase 2 (操作可能) の段階設計までやって本人の判断で停止。

## 主な変更

### Backend / FCM

- **FCM priority = HIGH**: `backend/src/fcm.ts` の `sendFcm` ペイロードに `android: { priority: 'high' }` を注入。data-only メッセージは normal priority がデフォルトで Doze 中に滞留 → 「アプリ開くまで来ない」現象の主因だった。Doze 貫通・端末 wake・kill 状態でも MessagingService 起動するようになる
- **migration 0013 `blocks`**: `turns.blocks` (TEXT) / `sessions.current_blocks` (TEXT) を追加。CC の jsonl の `[text, tool_use, text, tool_use, ...]` 順序を JSON で丸ごと保存する schema
- **migration 0014 drop legacy**: `turns.assistant_text` / `turns.tool_calls` / `sessions.current_assistant_text` を DROP。blocks 移行で読み書きされなくなった列を schema から除去
- **`HookStopRequest.blocks`**: 旧 `full_message` + `tool_calls` の 2 並列フィールドを廃止、順序保持の 1 配列に統合。`hooks.ts` は blocks から `assistant_text` を導出して FCM body preview に使うだけ
- **`WaitRequest.current_blocks`**: heartbeat も同様に blocks 化。in-flight 中の tool_use が phone 上にリアルタイムで見える (前はテキストだけ)
- **`supports_always` フラグの一元化**: `channel.mjs` の `deriveAllowPattern` が真のソースなので、channel.mjs 側で計算して `/v1/approvals` POST 時に同梱。backend は `tool_input` JSON に同居保存して FCM / sessions response に転送するだけ。`backend/src/format.ts` の `supportsAlways()` ヘルパーを削除して二重管理を解消

### Channel + Hooks

- **`assistantBlocksAfterFromJsonl` を heartbeat と Stop hook の両方で使う**: jsonl の text + tool_use を順序通り抽出する関数は既に存在していて、Stop hook 側ではそれを使って 2 並列フィールドに分解していた。分解せずそのまま送るだけで順序問題が解消
- **`assistantTextsAfterFromJsonl` 削除**: text-only join を返す関数。blocks 化で利用箇所がなくなった
- **channel.mjs `supports_always`**: 上述の通り、`deriveAllowPattern(tool_name, input_preview) != null` を計算して送る

### Android

#### blocks 描画

- **`Block` model**: kotlinx.serialization の sealed class は discriminator 設定が要るので、`kind` + 可空フィールドの単一 data class にした (`kind: String, text: String?, name: String?, input: JsonObject?`)
- **`BlockList` Composable**: TurnBlock / InFlightBlock 共通の描画器。`kind` で text → `ChatMarkdown`、tool_use → `ToolCallBlock` に分岐
- **`Turn.blocks` / `SessionDetailHeader.current_blocks`**: 旧 `assistant_text` / `tool_calls` / `current_assistant_text` を撤去
- **`InFlightBlock(prompt, blocks)`**: live narration を blocks で受けるので、in-flight 中の Bash 実行や Edit の差分がリアルタイムで phone 上に流れる

#### tool_use 描画拡張

- **`ToolCallBlock` の専用 case 追加**:
  - `TaskCreate · <subject>`
  - `TaskUpdate · #<id> → <status>` / `#<id>`
  - `TaskGet/Stop/Output · #<id>`
  - `Agent · <subagent_type> · <description>`
  - `WebSearch · <query>`
  - `ScheduleWakeup · <delay>s · <reason>`
- **汎用フォールバック**: 未知ツール向けに `subject, description, query, prompt, reason, name, title, body, text, command, path, skill, libraryName, libraryId` を順に当たって最初に見つかった文字列を target に
- **MCP ツール名整形**: `mcp__plugin_context7_context7__query-docs` → `query-docs` のように末尾セグメントだけ表示
- **`ToolHeader.target` を 1 行固定 + 横スクロール**: 折り返すと header が縦に伸びてリスト視認性が落ちる。Bash の `CodeBlock` の horizontalScroll に揃えた。タップ (no drag) は accordion 展開・clickable に届く

#### Bash ハイライト無効化

- **`BashRow` で `language = null`**: `SyntaxLanguage.SHELL` の keyword 表は `git` / `npm` / `curl` 等の実コマンドと噛み合わず誤強調が目立つ。プレーン monospace に統一
- **`Languages.kt` から SHELL alias 削除**: `.sh` ファイルを Edit/Write した時の差分も同じく plain になり、Bash と一貫

#### Always ボタン条件分岐

- **`ApprovalPayload.supportsAlways`**: FCM data の `supports_always` (`"true"`/`"false"`) を解釈。古い backend の互換のため不在時は `true` 倒し
- **`NotificationFactory.showApproval`**: `supportsAlways` が false の時は Always action ボタンを出さない (Allow / Deny の 2 択)
- **`PendingApproval.supports_always` + `PendingApprovalBlock`**: 画面内の Always ボタンも同様に条件分岐

#### 音声入力

- **`PromptInputBar` に mic IconButton**: `RecognizerIntent.ACTION_RECOGNIZE_SPEECH` を `ActivityResultContracts.StartActivityForResult` で起動。`ja-JP` 固定、結果は既存テキストに半角スペース区切りで append
- **AndroidManifest `<queries>`**: Android 11+ の package visibility 制約で `android.speech.action.RECOGNIZE_SPEECH` を解決できるよう追加。`RECORD_AUDIO` 権限は不要 (system UI 側が持つ)

### セルフレビューで拾った cleanup

- `hooks.ts` で FCM info ペイロードに `full_message: fullMessage` を送っていたが Android 側が読んでない dead data だったので削除
- `channel.mjs` の `current_assistant_text` への言及コメントを `current_blocks` に追従
- `hooks/lib/jsonl.mjs` の `assistantBlocksAfterFromJsonl` docstring に残っていた "callers derive assistant_text + tool_calls" の解説を blocks ベース表記に直し
- `backend/src/types.ts` の `TurnRow.tool_calls`, `SessionRow.current_assistant_text` を削除

## 設計だけ済ませて保留

### AskUserQuestion relay

Phase 1 (notify-only) / Phase 2 (操作可能) の 2 段階設計まで。Phase 2 は PreToolUse hook で `deny + systemMessage` でローカル UI を抑制 → phone 専用にする路線だが、systemMessage 経由の擬似回答を Claude が素直に解釈するか未検証。設計詳細は当ターン内のチャットに残っているので、再開時はそこから参照。
