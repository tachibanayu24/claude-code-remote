# 2026-05-04 初期設計と方針決定

misc リポジトリで開始した「Claude Code の通知をスマホ・Fitbit に飛ばしたい」という相談から、本リポジトリ立ち上げに至るまでのセッションログ。

## 流れ

1. **課題提起**: VS Code ターミナルで複数 Claude Code を並行運用しているが、入力待ち・完了に気づきづらい。スマホ / Fitbit / mac 通知を希望、音は不可（外出先利用のため）
2. **2026-05-04 時点のベストプラクティス調査**:
   - Claude Code hooks の Stop / Notification / SubagentStop / UserPromptSubmit を整理
   - 通知サービス: ntfy.sh / Pushover / Pushbullet / Bark / Pushcut を比較
   - Mac 通知: terminal-notifier / osascript の使い分け
   - Fitbit は直接 API なし、スマホ通知のミラーリングのみ
3. **構成決定**: ntfy.sh + Android で進める。iOS は不安定なので除外
4. **疎通確認**:
   - 過去にユーザーが setup していた topic `claude-code-tachibanayu24` が判明
   - `https://ntfy.sh/claude-code-tachibanayu24` への curl 送信でスマホ・Fitbit 両方に届くことを確認
5. **方向性の転換**:
   - ntfy アプリのアイコンが好みでない
   - 拡張性（Approve/Deny の遠隔操作、追加指示送信、ダッシュボード）の魅力
   - → 自作 Android アプリ路線へ
6. **拡張可能性の調査**:
   - PreToolUse hook の stdout で `{"behavior": "allow"|"deny"}` を返せば承認を外部判断にできることが公式仕様で確認
   - claude-remote-approver / Claude-Code-Remote / cc-sessions の3つの OSS 実装を確認
   - 公式 Channels 機能（Telegram/Discord/iMessage プラグイン、permission relay は research preview）の存在
7. **本リポジトリ立ち上げ**: misc から切り離して `~/Workspace/tachibanayu24/claude-code-remote/` へ移管

## 決定事項

- 対象 OS: Android のみ
- 通知 topic: `claude-code-tachibanayu24`（既存利用継続）
- アーキテクチャ: 自作 Android アプリ + ローカルバックエンド + Claude Code hooks の3層
- バックエンドは Mac の localhost で動かす（外出先は Tailscale 経由）
- FCM か ntfy セルフホストかは未確定（Phase 1 で決める）
